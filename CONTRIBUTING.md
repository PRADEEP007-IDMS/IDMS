# Contributing to IDMS

Thank you for your interest in contributing to the Integrated Data Management System!

## Code of Conduct

Please follow ethical and professional standards when contributing.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/YOUR-USERNAME/IDMS.git`
3. Create a feature branch: `git checkout -b feature/your-feature-name`
4. Make your changes and commit: `git commit -m "Add description of changes"`
5. Push to your fork: `git push origin feature/your-feature-name`
6. Open a Pull Request

## Development Guidelines

### Code Style

- Use ESLint for JavaScript/TypeScript
- Follow Prettier for code formatting
- Use meaningful variable and function names
- Add comments for complex logic

### Commit Messages

Use conventional commits:

```
feat: add new feature
fix: fix a bug
docs: update documentation
style: code style changes
refactor: refactor existing code
test: add tests
```

### Testing

- Write tests for new features
- Ensure all tests pass before submitting PR
- Target ≥ 80% code coverage

### Pull Request Process

1. Update documentation if needed
2. Add/update tests
3. Ensure CI/CD passes
4. Request review from maintainers
5. Address review comments

## Reporting Issues

Use GitHub Issues to report bugs or suggest features. Include:

- Clear description of the issue
- Steps to reproduce (for bugs)
- Expected vs actual behavior
- Environment details

## Questions?

Open an issue or contact the development team.
